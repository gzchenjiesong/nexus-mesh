# 验收场景设计手册

> **用途**：在决定上云部署前，确认"到底实现到什么程度"，并据此设计验收场景。
> 本文所有条目都从代码与测试提取，不是凭记忆列的。
>
> 生成于 `main @ v0.11.0`，15 模块 / 114 功能点 / 23 模块需求 / 19 安全要求。

---

## 〇、先看这一页：能力边界

| 分类 | 数量 | 说明 |
|---|---|---|
| 模块总数 | **15** | M1–M15 |
| 已实现 | **12** | 110 个功能点 |
| 部分实现 | **2** | M8 会话任务图（只有视图）、M9 产物通道（只有引用形态） |
| 未实现 | **1** | M2 协议适配（A2A 等外部协议） |

### 一句话概括

**能做的**：跨域、跨网络、有双向权限校验与应答边界、可断电自愈的 A2A 任务协作。
**不能做的**：对外协议互转、mTLS、任务依赖编排、大产物带外传输。
**界面**：有只读观察窗（M15），但只能看，不能改。

## 一、可以验收的能力（按验收目的分组）

### A. 核心闭环 —— 一个任务真的能跑完

**验收点**：任务从投递到结果回传，全链路无损。

| 步骤 | 怎么验 | 通过判据 |
|---|---|---|
| A1 注册 | 节点启动，调 `register` | **见下方 ⚠**：`created` 或 `unchanged`，两者都算正常 |
| A2 批准 | `nxs ops approve <节点>` | 返回 `approved=true`；节点下次心跳变已批准 |
| A3 投递 | `publish` 指定 `to_node` | 返回 `task.id`、`created=true` |
| A4 领取 | 节点 `poll` | 返回任务，状态转 `working`，`attempt` +1 |
| A5 执行 | SDK `execute(task)` | 状态转 `completed`，产出经**两层边界** |
| A6 结果 | 读任务的 `artifacts` | 字段在 `response_fields` 内、等级 ≤ 上限 |

> ⚠ **A1 的 `outcome` 取决于节点是否已预注册**，这不影响验收：
>
> | 情形 | `outcome` | 何时发生 |
> |---|---|---|
> | 节点不在配置里（真实部署的常态） | `created` | 首次自注册 |
> | 节点已在配置 `nodes:` 列表里 | `unchanged` | 配置加载时已注册，注册即心跳 |
> | 卡片内容变了 | `card_changed` | 改了角色卡 |
>
> **三种情况都应该 `approved=false`**（除非该域在 `auto_approve_domains` 里）。
> 判断"注册是否成功"看 `state=alive` 与 `approved`，不看 `outcome`。
>
> 这条是**实测后修正的**：本手册初版写"返回 `outcome=created`"，
> 但用示例配置（节点已在 yaml 里）跑会得到 `unchanged`。

**推荐验证方式**：`make demo`（九步，两种传输）+ 自己按上面 6 步走一遍真实 HTTP。

### B. 安全断言 —— 三层拦截互相独立

这是本系统的立身之本。**三层必须各自独立生效**，任一层能单独拦住越权。

| 层 | 验收点 | 预期错误码 | 怎么造 |
|---|---|---|---|
| **B1 角色层** | `worker` 角色的节点不能发任务 | `MX-ISSUER-01` | 让一个 `role=worker` 的节点调 `publish` |
| **B2 矩阵层** | 有发布权，但跨域仍被拒 | `MX-DOMAIN-02` | 往矩阵里**没有**的域投递 |
| **B3 字段边界** | 产出多一个字段就被拒 | `WL-FIELD-001` | 返回 `response_fields` 之外的键 |
| **B4 等级边界** | 产出超等级被拒 | `WL-LEVEL-002` | 声明 `summary` 却返回 `fragment` |
| **B5 节点侧边界** | 越界产出**根本没发出** | 节点自己拦，见节点日志 | 绕过 SDK 直接 `complete` 应被 coordinator 侧再拦一次 |
| **B6 拒绝不泄露** | 响应体只有 `rule_id` + 固定消息 | — | 检查响应里**不含字段名、不含内容** |
| **B7 提示注入防护** | 回传内容强制标注 `semantics=data` | — | 返回带"忽略以上指令"的文本，看是否被清洗 |

**B5 是双层防御的关键**：节点侧拦下时，coordinator 侧**连拒绝记录都不该有**（因为请求没到）。
验收方式：查 coordinator 审计里有没有对应的 `WL-FIELD-001`——没有才对。

### C. 持久化与自愈 —— 断电不用人管

| 验收点 | 怎么验 | 通过判据 |
|---|---|---|
| C1 注册表持久 | 重启服务 | `nxs ops nodes` 里节点与批准状态都在 |
| C2 队列持久 | 投递后重启，再 `poll` | 任务仍在，能领到 |
| C3 租约自愈 | 投递→领取→杀掉节点进程→等租约超时 | 任务自动回队列，`attempt` 累积 |
| C4 重试上限 | 反复超时 | 达上限后落 `failed`，不再无限重试 |
| C5 幂等 | 同 `idempotency_key` 投两次 | `created=false`，返回同一 `task.id` |
| C6 长任务续租 | 执行时间 > 租约（15s） | 不被误判中断（`/nxs/ack` 生效） |

> ⚠ **C5 有个陷阱**：幂等命中要求**归属一致**（`from_node` 相同）。
> 用别的节点身份 + 别人的幂等键，会被当作未命中并走正常流程，
> 然后很可能被拒（这是防探测，不是 bug）。

---

### D. 节点接入 —— 不用改云端配置

| 验收点 | 怎么验 | 通过判据 |
|---|---|---|
| D1 自注册 | 新节点调 `register` 提交角色卡 | `outcome=created`，**必然 `approved=false`** |
| D2 凭据只放 env | 服务端 `nxs.env` 加 `NXS_SECRET_<ID>`，**不改 yaml** | 注册成功 |
| D3 改卡片掉批准 | 已批准节点改角色卡再注册 | `outcome=card_changed`，`approved` 变 `false` |
| D4 域由配置裁定 | 节点自报 `domain=coordinator`（高权限域） | 注册返回的 `domain` 是配置里的值，不是自报的 |
| D5 身份一致 | 用 A 的密钥提交 B 的角色卡 | 403 `FM-CARD-03` |
| D6 吊销即时生效 | `nxs ops revoke` 后立刻调 API | 401 `AU-CRED-03`，不用等凭据过期 |

> ⚠ **D2 仍需重启服务**（环境变量在启动时固定）。不是"零重启"，是"少改一步"。

---

### E. 自动匹配 —— 不指定目标也能派活

| 验收点 | 怎么验 | 通过判据 |
|---|---|---|
| E1 按能力选 | `publish` 省略 `to_node` | 自动选中提供该能力的节点 |
| E2 确定性 | 同输入连算多次 `nxs candidates` | 顺序**完全一致** |
| E3 负载避让 | 占满 node-a 的并发后再投 | 自动改投 node-b |
| E4 统一失败码 | 无提供者 / 候选全被拒 | **两者都报 `WL-TYPE-404`** |
| E5 候选不外泄 | 请求 `/nxs/candidates` | 返回 501（无此端点） |

> E4 是安全设计：若能区分"没人能干"和"有人但不给你"，就泄漏了权限布局。
> 真实原因要看 coordinator 的审计日志。

### F. 运维与观测

| 验收点 | 怎么验 | 通过判据 |
|---|---|---|
| F1 远程批准/吊销 | `nxs ops approve\|revoke --url` | 立即生效，不需要重启 |
| F2 释放租约 | `nxs ops release --url` | 返回 `released` 与 `marked_stale` 计数 |
| F3 运维动作留痕 | 查审计 | 有 `outcome=ops:*` 记录（谁在何时给谁放行） |
| F4 节点读不到指标 | 用节点密钥调 `/nxs/ops/metrics` | **403** |
| F5 指标真实 | 跑几个任务后 `nxs metrics --url` | 提交/完成/延迟分位数都动起来 |
| F6 组合告警 | 制造"先正常后卡死" | 报 `silent_stall`（critical） |
| F7 试探识别 | 一个节点撞 ≥3 种拒绝规则 | 报 `probe_pattern`（critical） |
| F8 健康时不乱报 | 正常跑业务 | **零告警** |

> F8 同样重要：告警天天响就没人看了。**"不该报的没报"要和"该报的报了"一起验。**

## 二、**不能**验收的（别浪费时间设计这些场景）

| 不能做的事 | 现状 | 影响你的场景设计 |
|---|---|---|
| **mTLS（双向证书）** | 只有 HMAC 共享密钥 | 不要设计"客户端证书轮换"类场景 |
| **A2A / 外部协议互转（M2）** | 未实现 | 不要设计"接 Claude Agent / OpenAI 协议"类场景 |
| **任务依赖编排（DAG）** | M8 只有**状态视图**，不跟踪依赖 | 不要设计"任务 B 依赖任务 A 完成"类场景 |
| **产物带外传输（一次性令牌）** | 未实现 | 大文件只能"传坐标"，能否取到取决于你的存储约定 |
| **清空队列** | M14 未实现 | 只能用 `release` 释放租约 |
| **熔断某条链路** | M14 未实现 | 只能 `revoke` 整个节点 |
| **暂停某类型任务** | M14 未实现 | 只能改矩阵 + 重启 |
| **多 coordinator 联邦 / 中继** | 角色集没有中继 | 不要设计"多节点级联"场景 |
| **Prometheus 导出** | 只有 `--json` | 指标要自己转发 |
| **参数 schema 校验** | 只声明、不校验 | 参数写错不会在投递时被拦，会由执行节点失败 |
| **Postgres / Redis / Kafka** | 只有 memory 与 sqlite | 不要设计"接外部队列"场景 |

### 关于界面：现在有只读观察窗（M15）

**v0.10.x 之前这里是"零前端代码"。现在有了 `nxs ui`，但**只读**。**

| 面 | 形式 | 能做什么 |
|---|---|---|
| **`nxs ui`** | 本机网页（127.0.0.1） | **只读**：节点列表（名称/简介/角色/状态/能力）+ 系统汇总（计数/延迟分位数/异常） |
| `nxs` CLI | 终端文本 | 9 个命令：verify / doctor / demo / serve / ops / candidates / metrics / status / **ui** |
| SDK | Python 代码 | 节点侧完整能力：注册、领取、执行、续租、发布 |
| `/nxs/events` | SSE 文本流 | 只推"有活了"的通知，**不含任何业务数据** |

**网关本身仍然一个 HTML 都不返回** —— 8 个端点全是 JSON 或状态码
（`/nxs/events` 是 `text/event-stream`）。观察窗是**独立进程**，
这与网关的分离是有意的：网关的信任模型是 HMAC 机器身份，
塞进浏览器 cookie 那套会把它弄脏。

**观察窗不是网络里的节点。** 它走 ops HTTP 通道读数据，没有节点身份、
不参与任何任务投递。「有界面」指的是 `nxs ui` 这个独立进程，
不是角色卡上的某个字段 —— 角色集里没有"人机入口"这个角色。

#### 怎么验观察窗

```bash
# 服务器上
nxs ui --url http://127.0.0.1:18100/nxs --port 8080
# 输出里会打印：http://127.0.0.1:8080/?t=<token>

# 你电脑上建隧道
ssh -N -L 8080:127.0.0.1:8080 user@服务器

# 浏览器打开那个带 token 的链接（token 会立刻换成 cookie，URL 恢复干净）
```

| 验收点 | 怎么验 | 通过判据 |
|---|---|---|
| 只读 | 页面找任何"批准/吊销"按钮 | **没有**。改状态只能用 `nxs ops` |
| 鉴权 | 不带 token 直接访问 | 401 |
| token 不落盘 | 重启 `nxs ui` | token 变了；旧链接失效 |
| 只听本机 | `nxs ui --host 0.0.0.0` | 拒绝启动，并提示用 SSH 隧道 |
| 写方法 | `curl -X POST .../api/state` | 405 + `Allow: GET` |
| coordinator 挂了 | 停掉 coordinator 再刷页面 | 显示"coordinator 不可达：…"，**不是白屏** |
| 名称/简介 | 看节点行 | 显示 `display_name` 与 `description` |

> ⚠ **验收时注意**：`display_name` / `description` 是节点自报的。
> 服务端已拒控制字符（防终端/日志注入）与超长，但**没做 HTML 转义**——
> 转义在渲染层做（页面用 `textContent` 建 DOM，结构上不解析标记）。
> 想验这条：把某个节点的名字填成 `<img src=x onerror=alert(1)>`，
> 页面上应该**显示这段文字本身**，而不是执行它。

## 三、**配了但不生效**的项（最危险的一类）

这些配置会被正常解析、会出现在 `nxs verify` 输出里，**但不产生任何行为**。
权威清单是 `nxs/mgmt/config.py` 的 `UNIMPLEMENTED`。

### 当前状态：清单只剩 1 项

| 配置项 | 实际不生效 |
|---|---|
| `params_schema` | 参数不校验。格式错误的参数会被投递出去，由执行节点自己承担失败 |

> **权限模型改造（进行中）会把它也消掉**：TaskType 改为 Mesh 全局定义后，
> 校验方与定义方是同一个，`params_schema` 才能真的校验。
> 详见 [`design/06-agent-role-model.md`](design/06-agent-role-model.md)。

### 其余 6 项的去向（不再是"不生效"，而是"不存在了"）

改造前这里列着 6 项"配了但不生效"，它们共同的特征是
**配置项本身就不该存在** —— 一个需要专门写说明解释"它不生效"的字段，
是设计问题的信号，不是文档问题。

| 原配置项 | 处置 |
|---|---|
| 单次 / 按日应答字节上限 | 配置项**删除**。这类限额归节点自律（`self_limits`），Mesh 不再管 |
| 中继 / 观察者 / 人机入口三类角色标志 | 字段**消失**。角色集只有 `worker`/`driver`/`publisher` |
| 执行者角色标志 | 字段**消失**。声明了能力就是愿意被委托，不需要额外开关 |

> ⚠ **曾经有一整段解释「关闭执行者标志为什么不会阻止它干活」的说明。**
>
> 那段说明讲的是 2026-10-27 的一次实测：`executor: false` 但声明了能力的节点，
> 照样能走完投递 → 领取 → 执行 → 回传；真正的闸门是 `capabilities` 声明。
>
> 它现在被删掉了，新模型里没有这个字段，也就没有这个困惑。

## 三之二、验收时**不要**设计的场景（改造后）

| 别测什么 | 为什么 |
|---|---|
| "关闭某个角色的执行开关后它不能干活" | 没有这个开关。要限制就是不批准它以该 role 加入 |
| "按日任务数 / 字节配额用尽会被拒" | 配额归节点自律，Mesh 不拦。节点自己会申报 `paused` |
| "并发满了会排队等我" | 信箱本来就是排队。并发不设上限，只受 `max_backlog` 限制 |
| "多 coordinator 联邦 / 中继" | 没有中继角色 |

## 四、几个会影响验收设计的实现细节

这些不是缺陷，但会让"看起来该通过的东西不通过"。

| 细节 | 说明 |
|---|---|
| **信封上限 ~186 KB 文件** | base64 膨胀 33%。更大的产物必须走 `kind=reference` 传坐标 |
| **租约默认 15 秒** | 长任务靠 `renew_interval`（默认 5s）自动续租，不靠调大租约 |
| **域矩阵只表达可达性** | 不再列任务类型。类型权限由 role 决定，域只管「这批数据能被谁触达」 |
| **每个节点都要批准** | `auto_approve_domains: []` 对所有人一视同仁，没有任何节点免批 |
| **`to_node=""` 才是自动匹配** | 漏写 `to_node` 报 `FM-SCHEMA-01`，不是自动 |
| **`kind="freetext"` 必须声明** | 能力没声明 `freetext_fields` 却回 `kind=freetext` → 被拒 `WL-FREETEXT-003` |
| **指标重启归零** | 是内存态。跨重启趋势看审计日志 |
| **趋势类告警要两次调用** | `silent_stall` 需对比上一次快照，第一次调可能少一条 |
| **`outcome` 有三分支** | `created` / `unchanged` / `card_changed`。判"注册成功"看 `state` 与 `approved`，别看 `outcome` |

### ⚠ 验收时最容易踩的一个坑：前一个任务没落终态

**并发不再设上限**（信箱就是排队），所以"名额被占住"这类问题消失了。
但**同类陷阱换了个形式**，而且更隐蔽：

```
① 投递任务 A → 领取 → 产出被边界拒绝
② 任务 A 停在 working —— 它占着租约，但不再阻塞后续投递
③ 再投递任务 B → 投递成功
```

现在的问题不是"投不进去"，而是 **A 卡在 working 状态没人管**：

- 它会一直占着一条租约，直到 `LF-EXPIRE-02` 超时
- 指标里 `in_flight` 会一直挂着，看起来像节点卡了
- 如果反复这样做，`pending` 会累积，最终撞上 `max_backlog` → `QT-BACKLOG-07`

**验收时的做法**：

- 每条会失败的安全断言之后，**显式让任务落终态**（`fail` 或等租约超时）
- 或调 `nxs ops release` 释放租约
- 验收看的是拦截逻辑，不是队列行为 —— 别把两者混在一起

> 这条源自写本手册的抽查脚本时的实测（`examples/acceptance_drill.py`
> 初版在 B3 之后卡住）。当时是并发配额，现在是租约未释放 ——
> **陷阱的形态跟着机制变了，但"忘了收尾"这个根因没变。**

## 五、建议的验收场景骨架

按"出问题最想先知道"排序。**前四组任一不通过，就不要上云。**

```
第一轮 · 核心闭环（必过）
  ├─ make demo / make demo-net                    九步全过
  ├─ 真实 HTTP 走 A1–A6                            任务跑完
  └─ C1/C2 持久化                                  重启不丢

第二轮 · 安全断言（必过）
  ├─ B1 角色层：无发布权被拒
  ├─ B2 矩阵层：跨域被拒
```

## 六、这份清单怎么复核

```bash
# ① 自动抽查：按本手册的条目验一遍（21 项）
python examples/acceptance_drill.py

# ② 八步/九步 demo（两种传输）
make demo && make demo-net

.venv/bin/python -m nxs doctor --config deploy/local.yaml.example --production
```

**① 是最该先跑的。** 它不只是跑测试——它验证**本手册写的东西是不是真的**。
初版写这份手册时，它就抓到了两处手册自己的错误：

* 手册说 A1 注册返回 `outcome=created`，实际示例配置返回 `unchanged`
* 手册没提"失败任务不落终态会占满并发配额、卡住后续投递"

两处都已修正并写进上面的注意事项。

> 本文档里的事实性声称（模块状态、功能点数、端点、错误码、不能验收清单、
> 配了不生效清单）由 `tests/test_docs_consistency.py` 守护。
> 若它们变了，测试会红 —— 包括"这个文档说了过时的话"这种情况。

### 自动化的边界

`acceptance_drill.py` 只覆盖**单机可自动化**的部分。以下必须手工验：

| 必须手工 | 为什么 |
|---|---|
| systemd 启停与重启策略 | 需要真实 systemd |
| TLS 握手（如果不用前置代理） | 需要真实证书 |
| 跨机器网络（防火墙、DNS、出口） | 需要两台机器 |
| 前置代理的 SSE 不缓冲 | 需要真实 Nginx/Caddy |
| 断电恢复（真的 kill -9） | 抽查脚本里是模拟租约超时 |

实测过前四项之前，**不要认为"部署成功"**。
